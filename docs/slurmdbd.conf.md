## NAME

slurmdbd.conf - Slurm Database Daemon (SlurmDBD) configuration file

## DESCRIPTION

**slurmdbd.conf** is an ASCII file which describes Slurm Database
Daemon (SlurmDBD) configuration information.
The file will always be located in the same directory as the **slurm.conf**.

The contents of the file are case insensitive except for the names of nodes
and files. Any text following a "#" in the configuration file is treated
as a comment through the end of that line.
Changes to the configuration file take effect upon restart of
SlurmDBD or daemon receipt of the SIGHUP signal unless otherwise noted.

This file should be only on the machine where SlurmDBD executes, owned by the
SlurmUser or root, and have permissions set to 600 or 640.
If the slurmdbd daemon is started as user root and changes to another
user ID, the configuration file will initially be read as user root, but will
be read as the other user ID in response to a SIGHUP signal.
This file should be protected from unauthorized access since it
contains a database password.
The overall configuration parameters available include:

**AllowNoDefAcct**

If not set (default), then transaction records are never purged. : **PurgeUsageAfter** : Automatically purge usage records (Cluster, Association, QOS and WCKey) older than the stated time (based on creation or last modified time). These tables are the source for reports generated by the [sreport](sreport.md)(1) command. Units are months (default), days, or hours. The purge occurs at the start of each month, day, or hour, depending on which unit is used. For example, the values "2months" and "60days" would affect roughly the same records, but the latter would execute the purge daily instead of monthly. If not set (default), then usage records are never purged. : **SerializerParameters** : Comma-separated list of flags passed to the serializer plugins. Not every flag applies to every plugin; each flag below names the plugins that honor it. **NOTE**: These flags are applied once, when **slurmdbd** starts. Changes to this option are not picked up by **sacctmgr reconfigure**; they require a restart of **slurmdbd**. : : **compact** : Use compact output with minimal whitespace. : **pretty** : Use human-readable output with indentation and newlines. This is the default. : **complex** : Include the special floating-point values Infinity and NaN directly. By default **serializer/json** replaces them with placeholder numbers and **serializer/xjson** replaces them with **null**, which keeps the output parsable by any JSON parser. : **NOTE**: Output produced with this flag is not strict JSON. The bare tokens **Infinity**, **-Infinity** and **NaN** are emitted, and **serializer/xjson** may also emit **-NaN**, all of which RFC 8259 parsers reject. : **json6** : Dump using the JSON6 grammar where RFC 8259 has no equivalent, rather than substituting. Currently this affects byte sequences that Slurm will not emit as JSON text: bytes that are not well formed UTF-8, and valid UTF-8 encodings of code points Slurm rejects by policy (U+0000, surrogates, noncharacters, private use, and U+FFF0 through U+FFF8). These are emitted as **\**x*NN* escapes, where *NN* is the hexadecimal value of one source byte. By default each such byte sequence is replaced with the Unicode replacement character (U+FFFD), which loses the original bytes. : **NOTE**: This escape is a deliberate exception to JSON6 and is not compliant with it. JSON6 and JSON5 both define **\**x*NN* as the code point U+00*NN*, which a reader then encodes as UTF-8. **serializer/xjson** instead writes and reads the single byte *NN*, with no UTF-8 or code point check. The two agree only for *NN* below 0x80, and **serializer/xjson** only ever emits the escape for bytes 0x80 through 0xff, so every escape it emits is decoded to different and longer text by a conforming JSON6 or JSON5 reader, with no error reported. The exception is intentional: writing the byte rather than the code point is what makes the output binary safe, so that any byte sequence survives a round trip. Only **serializer/xjson** recovers the original bytes. : Only the first class is genuinely unrepresentable. The rest are valid Unicode that RFC 8259 permits and that **serializer/json** emits unchanged; Slurm drops them by policy, not because JSON cannot carry them. : Only **serializer/xjson** honors this flag, and it affects serialization only. It does not change what the parser accepts: **serializer/xjson** always accepts the relaxed grammar on input, whether or not this flag is set. See **xjson** under **SerializerPlugins**. : **NOTE**: Output produced with this flag is not strict JSON and is rejected by parsers that only accept RFC 8259, including those in Python and Go. : **NOTE**: JSON6 support is incomplete. Only a subset of the JSON6 grammar is implemented, and which constructs are covered may change between releases. Do not rely on this flag for anything beyond the byte escaping described above. : **no\_tag** : Do not emit YAML tags. These tags ensure accurate preservation of data types; when set, some types may be inferred incorrectly. : **SerializerPlugins** : Comma-separated list of serializer plugins to load. Defaults to all serializer plugins found on the system. **NOTE**: Serializer plugins are loaded once, when **slurmdbd** starts. Changes to this option are not picked up by **sacctmgr reconfigure**; they require a restart of **slurmdbd**. : Acceptable values at present are: : : **json** : Serialize to and from JSON. **NOTE**: Default Slurm deployments require a serializer that provides the **application/json** MIME type. Either **json** or **xjson** satisfies this requirement; omitting both may cause daemons to fail at startup. : **json-patch** : Apply an RFC 6902 JSON Patch document to an existing JSON document. Provides the **application/json-patch+json** MIME type and requires **json** or **xjson** to parse the patch. Creating patches and serialization are not supported. : **xjson** : Serialize to and from JSON. Unlike **json**, this plugin is always built and requires no external JSON library. : The two plugins do not produce byte-identical output. Notably **serializer/xjson** dumps floating-point numbers in exponential notation and handles Infinity and NaN differently; see **SerializerParameters**. : Those differences preserve the value. One does not: **serializer/xjson** replaces code points outside the subset Slurm accepts with the Unicode replacement character (U+FFFD) unless **json6** is set, discarding the original bytes, while **serializer/json** emits them unchanged. This applies to every string field, including job names, **Comment** and node **Extra**. : The two plugins also differ on input. **serializer/xjson** rejects documents containing code points Slurm does not accept: U+0000, surrogates, noncharacters, private use, and U+FFF0 through U+FFF8. Most of these are valid Unicode that RFC 8259 permits and **serializer/json** parses, so a document that was accepted before may be rejected after changing plugins. The restriction applies to **\**u*XXXX* escapes as well as to literal bytes, and one rejected code point fails the whole document. : **\**x*NN* escapes are exempt from that restriction. Each one contributes its byte to the string with no UTF-8 or code point check, which is what allows **json6** output to be read back by **serializer/xjson** with the original bytes intact. A document may therefore use them to place a byte sequence in a string that **serializer/xjson** would never emit, including a sequence that is not well formed UTF-8. Dumping that string again replaces the offending bytes with the Unicode replacement character (U+FFFD) unless **json6** is set, but every other consumer of the parsed data sees the bytes as given. : In the other direction **serializer/xjson** is more permissive than RFC 8259: it also accepts comments, single quoted and unquoted strings, **\**x*NN* escapes and backslash-newline line continuations. This is unconditional and is not controlled by **json6**, so it applies to every JSON document **slurmdbd** parses, which is every token and credential **auth/slurm** or **auth/jwt** presents to it. **NOTE**: Only one plugin may serve a given MIME type. Both **json** and **xjson** provide **application/json**, and the plugin named first in **SerializerPlugins** serves it. When **SerializerPlugins** is not set, all plugins found on the system are loaded and which of the two serves **application/json** is not defined. : **NOTE**: **SerializerPlugins** replaces the default set of plugins rather than adding to it, so every plugin **slurmdbd** needs must be named. This setting applies only to **slurmdbd** itself; the value in **slurm.conf** governs every other daemon and command, including **sacctmgr**. : **slurmdbd** needs a plugin providing **application/json**, because **auth/slurm** and **auth/jwt** both require one. It needs neither **yaml** nor **url-encoded**: no **slurmdbd** configuration file is read as YAML, and **url-encoded** is used only by **slurmrestd**. So selecting **xjson** here needs only: : ``` SerializerPlugins=xjson ``` : **NOTE**: Naming a plugin that was not built is fatal, not ignored. **yaml** is only built when Slurm is configured with libyaml, and **json** is only built when it is configured with json-c, so omit either one from the list on a build without its library. **json-patch**, **xjson**, and **url-encoded** are always built. : **yaml** : Serialize to and from YAML. : **url-encoded** : Deserialize from URL-encoded form data. Parsing only; serialization to URL-encoded form is not supported. : **SlurmUser** : The name of the user that the **slurmdbd** daemon executes as. This user should match the SlurmUser used for all instances of slurmctld that report to slurmdbd. It must exist on the machine executing the Slurm Database Daemon and have the same UID as the hosts on which **slurmctld** executes. For security purposes, a user other than "root" is recommended. The default value is "root". **NOTE**: If the SlurmUser for slurmctld is root you can still use a non-root SlurmUser for slurmdbd (in any other case, both SlurmUsers should match) by explicitly setting the user's AdminLevel to Admin. After adding a user in this way, you must restart slurmctld. : **StorageBackupHost** : Define the name of the backup host the database is running where we are going to store the data. This can be viewed as a backup solution when the StorageHost is not responding. It is up to the backup solution to enforce the coherency of the accounting information between the two hosts. With clustered database solutions (active/passive HA), you would not need to use this feature. Can be a UNIX socket, e.g., "unix:/path/to/socket". Default is none. : **StorageHost** : Define the name of the host the database is running where we are going to store the data. This can be the host on which slurmdbd executes, but for larger systems, we recommend keeping the database on a separate machine. Can be a UNIX socket, e.g., "unix:/path/to/socket". Default is "localhost". : **StorageLoc** : Specify the name of the database as the location where accounting records are written. Defaults to "slurm\_acct\_db". : **StorageParameters** : Comma separated list of key-value pair parameters. : : **SSL\_CERT** : The path name of the client public key certificate file. : **SSL\_CA** : The path name of the Certificate Authority (CA) certificate file. : **SSL\_CAPATH** : The path name of the directory that contains trusted SSL CA certificate files. : **SSL\_KEY** : The path name of the client private key file. : **SSL\_CIPHER** : The list of permissible ciphers for SSL encryption. : **token\_duration** : Duration in seconds to cache generated database passwords before requesting a new one from the StoragePassScript. Typically the token should refresh prior to actual expiration; upon token generation failure the cached token will continue to be used to avoid transient generation failures from causing connection failures. Default value is 300 seconds (5 minutes). : **StoragePass** : Define the password used to gain access to the database to store the job accounting data. The '#' character is not permitted in a password. : **StoragePassScript** : Absolute path to an executable script that generates ephemeral authentication tokens for database connections which are used instead of **StoragePass**. The script must output the password/token to stdout and exit with status 0 on success. This allows dynamic password generation, instead of storing static credentials in configuration files. The script must be owned and executable by SlurmUser. : Environment variables provided to the script: : **SLURM\_STORAGE\_HOSTNAME** : Database hostname **SLURM\_STORAGE\_PORT** : Database port number **SLURM\_STORAGE\_USER** : Database username : Expected output format: **TOKEN=***<authentication\_token>* : The script must exit with status 0 on success, non-zero on failure. Any output to stderr will be logged as an error. If there is a backup host specified, the script will still be provided the main hostname and the same token is used for both hosts. : **StoragePort** : The port number that the Slurm Database Daemon (slurmdbd) communicates with the database. Default is 3306. : **StorageType** : Define the accounting storage mechanism type. Acceptable values at present include "accounting\_storage/mysql". The value "accounting\_storage/mysql" indicates that accounting records should be written to a MySQL or MariaDB database specified by the **StorageLoc** parameter. This value must be specified. : **StorageUser** : Define the name of the user we are going to connect to the database with to store the job accounting data. If no value is specified, the user that started the slurmdbd will be used. : **TCPTimeout** : Time permitted for TCP connection to be established. Default value is 2 seconds. : **TLSParameters** : Comma-separated options identifying TLS options. Supported values include: : : **ca\_cert\_file=** : Path of certificate authority (CA) certificate. Must exist on all hosts and be accessible by all Slurm components. File permissions must be 644, and owned by SlurmUser/root. Default path is "ca\_cert.pem" in the Slurm configuration directory : **dbd\_cert\_file=** : Path of certificate used by slurmdbd. Must chain to **ca\_cert\_file**. Should only exist on host running slurmdbd. File permissions must be 600, and owned by SlurmUser. Default path is "dbd\_cert.pem" in the Slurm configuration directory : **dbd\_cert\_key\_file=** : Path of private key that accompanies **dbd\_cert\_file**. Should only exist on host running slurmdbd. File permissions must be 600, and owned by SlurmUser. Default path is "dbd\_cert\_key.pem" in the Slurm configuration directory : **load\_system\_certificates** : Load certificates found in default system locations (e.g. /etc/ssl) into trust store. Default is to not load system certificates, and to rely solely on **ca\_cert\_file** to establish trust. : **security\_policy\_version=** : Security policy version used by s2n. See s2n documentation for more details. Default security policy is "20230317", which is FIPS compliant and includes TLS 1.3. : **TLSType** : Specify the TLS implementation that will be used. When set to a TLS plugin, **slurmdbd** requires TLS on inbound connections and closes any that is not TLS wrapped. Refer to the TLS guide for more details: <<https://slurm.schedmd.com/tls.html>> Defaults to **tls/none**. Acceptable values at present: : : **tls/none** : No TLS. This is the default. : **tls/s2n** : Use the s2n TLS plugin. : **TrackSlurmctldDown** : Boolean yes or no. If set the slurmdbd will mark all idle resources on the cluster as down when a slurmctld disconnects or is no longer reachable. The default is no. : **TrackWCKey** : Boolean yes or no. Used to set display and track of the Workload Characterization Key. Must be set to track wckey usage. This must be set to generate rolled up usage tables from WCKeys. The default value is no. **NOTE**: If TrackWCKey is set here and not in your various slurm.conf files, jobs that do not request a WCKey will be attributed to the user's default WCKey.
